# Bounded synthetic capacity qualification

The reproducible command is:

```powershell
node --import tsx scripts/qualify-community-capacity.mjs --out <new-absolute-external-evidence-directory>
```

It refuses an existing output, checkout destinations, linked ancestors and an
unqualified Node ABI. It creates only a fresh synthetic child runtime. The
parent writes the fixed dataset and limits before measurement; the child checks
that exact policy and ownership marker. Existing financial stores are never
opened. Evidence is retained, while successful generated runtime cleanup is
verified before PASS.

The fixed dataset contains2,000 transactions in5 accounts,200 source-backed
invoice records and200 exact accepted allocations, with independently generated
EUR/USD totals. Twenty-five report/serialization samples, canonical commits,
document import, a complete backup and verified SQLite/JSON reopen are measured.
Every report must preserve counts, exact currency totals and zero remaining
document balances. Backup and reopened canonical checksums must agree with the
same records. This measures persistence/accounting capacity; it does not claim
OCR throughput, remote-provider latency, large-archive capacity or concurrent
browser performance.

Predeclared upper bounds: report p95 2,000ms; serialization p95 1,000ms;
canonical commit30,000ms; backup30,000ms; verified reopen15,000ms; peak process
RSS1GiB. Every bound is an assertion; a failure remains a failed qualification.

Intermediate `capacity-01` passed under Node22.23.3/ABI127: report p95
15.09ms, serialization p95 12.96ms, commit max256.69ms, backup394.43ms,
reopen163.62ms and peak RSS194,387,968bytes. Expected totals are EUR-18,200
and USD-900 minor units. The external result records all samples' summary,
policy, hashes, cleanup and scope; command metadata identifies the source and
dirty state. The first run preceded the final script provenance/ABI guard and
does not certify a later commit. Final exact-candidate qualification is required.

No product, live-provider, legal or release acceptance is implied by this
bounded benchmark.

The complete sequential application group retains a 20-minute aggregate bound.
The expanded Node group has a 45-minute aggregate bound, and the hosted Windows
job allows 75 minutes for installation, build and both groups. Separate fresh
package installation journeys cover AIS, sandbox PIS, Stripe payouts, upgrades
and the integrated financial workflow. The historical d521 Node group took
1,435,425.5177ms; the separately added f330 PIS journey took 271,398.8114ms.
These are distinct observed durations, not a completed combined qualification.
Individual test deadlines, financial assertions, error checks and discovery
requirements are unchanged. An aggregate deadline failure remains a failed run.
