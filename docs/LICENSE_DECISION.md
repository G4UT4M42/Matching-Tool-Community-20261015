# Source license decision — MIT

Status: **MIT selected and maintainer rights confirmed for the original
application code.** Third-party components retain their own licenses.

The selected license for the original Matching Tool application source is
[MIT](../LICENSE). The maintainer requested publication of this repository as
open source on 2026-11-01 and subsequently confirmed holding the rights in
the inherited original application code. That declaration is recorded separately
from the bounded technical snippet screen; neither invents a legal review or a
cryptographic signature.

## Material covered

The maintainer's MIT grant covers original material in the published sanitized
history and current tree. The root license covers original application code, tests, scripts and project
documentation for which the contributors hold the necessary rights. Existing
copyright and attribution notices must be retained. New contributions are
submitted under the same license unless an explicit compatible exception is
reviewed and documented before merge.

External npm packages and their bundled code, trained OCR data, fonts, codecs,
native libraries and runtimes retain their respective licenses. A dependency
reference or generated inventory does not relicense those components under MIT.
See [NOTICE](../NOTICE), [the third-party index](../THIRD_PARTY_COMPONENTS.md)
and [the dependency evidence](compliance/README.md).

## Publication scope

The authorized publication is the sanitized source repository, including its
reviewed branches and history. No original V2 Git ancestry, real financial data,
browser sessions, third-party binaries, font files or banking XSD files are
included. Prepared Windows installers, source-built native replacements and
runtime archives remain separate artifacts with separate distribution duties.
They are not released or legally cleared by changing repository visibility.

The historical private-scope and engineering reports remain evidence for their
recorded artifacts; their old blanket publication flags do not describe a later
approved source-only release. Likewise, the source publication does not turn
historical binary-package flags into approval. Automated inventory fields such
as `sourceOwnershipVerified: false` mean the collector itself does not attest
ownership; the actual maintainer declaration must be assessed separately.
