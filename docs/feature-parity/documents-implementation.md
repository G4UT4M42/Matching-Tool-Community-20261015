# Community documents, recognition and Invoice Bot implementation

Status: isolated worker implementation and synthetic qualification, 2026-10-14. No production route activation or external commercial portal qualification is claimed.

## Source audit and design decisions

The preserved [F04/F10/F11 audit](../release-program/FEATURE_PARITY_AUDIT_20261013.md) marks document upload/open, OCR and Invoice Bot as blocked in Community. The P10-W01/W02 packages call for adapter inventory, controlled browser sessions, deduplication and cancellation. P11-W01/W02 concern payment preparation and submission; this worker does not create a payment candidate or execute a transfer. Legacy `src/import/document-import.ts` accepts a filesystem path and uses invoice/income parsers that default missing amounts to zero. Legacy `src/invoicerec/extract-ocr.ts` silently falls back to a CDN for language assets. Legacy `src/server/routes/invoicebot.ts` uses a shared `_default` browser profile and includes raw provider error text. None of these handlers were activated.

Legacy adapter source inventory, based on `src/invoicebot/portal-adapters/index.ts`: `amazon`, `browser_use`, `openai`, `chatgpt`, `aliexpress`, `google_cloud`, `google_one`, `bambulab`, `post_at`, `spotify`, `fiverr`. Source presence does not qualify login, invoice discovery, download, rights or safe profile handling for any of them. The new coordinator accepts only explicitly registered `PortalAdapter` implementations. The only exercised adapter is a local synthetic fixture injected by tests; its `allowLocalTestAdapter` flag must never be exposed by production HTTP configuration.

## Implemented surfaces

- `CommunityDocumentService` accepts bounded in-memory PDF, PNG and JPEG uploads and strict CSV/XLSX invoice/income tables. Filenames cannot become paths. Workspace-scoped SHA-256 blobs are immutable; the index uses atomic replacement and records owner, history, recognized text and confidence. Confirmation calls the injected `persistAndActivate(expectedState,nextState,actor)` callback before marking a review item confirmed. A failed callback leaves review evidence and an orphan blob that can be recovered or removed by maintenance. Index reopen reconciles a confirmed financial record after an interrupted index update.
- PDF intake uses pdfjs to parse and bound pages and dimensions, rejects active names, encrypted/object-stream PDFs, attachments, JavaScript actions and annotations. PNG/JPEG use sharp metadata and full decode under a 20 million pixel cap. PDF text is extracted by pdfjs; scanned single-page PDF rendering uses pdfjs with its own `@napi-rs/canvas` implementation, followed by Tesseract. Image OCR also uses Tesseract. Local `eng.traineddata` is required for OCR; no personal API key or automatic CDN fallback is used.
- Parsed invoice fields are review suggestions. Missing or conflicting currency, amount, date or invoice number is surfaced as a warning. No document becomes a financial `Document` until a user supplies and confirms complete exact fields. Review history records corrections, confirmation, rejection, archive and restore. Accepted match evidence cannot be archived through the ordinary route. CSV/XLSX rows preserve exact source IDs and reject formula cells, invalid dates, ambiguous decimals, duplicate IDs and oversized ZIP expansion.
- Routers enforce `res.locals.communityPrincipal.subject` and `.workspace_id` plus injected authorization. Document methods: `GET /`, `POST /upload`, `POST /import/:kind`, `GET /:id`, `GET /:id/content`, `PUT /:id/fields`, `POST /:id/confirm`, `POST /:id/reject`, `POST /:id/archive`, `POST /:id/restore`. Bot methods: `GET /portals`, `GET /runs`, `GET /runs/:id`, `GET /portals/:id/status`, `POST /portals/:id/connect`, `POST /portals/:id/disconnect`, `POST /portals/:id/discover`, `POST /runs/:id/import`, `POST /runs/:id/cancel`. All listed routes are relative to their mount points below.
- `InvoiceBotCoordinator` owns no credentials. An injected `BrowserSessionCallbacks` implementation opens, checks and disconnects a fresh user session. Registered adapters discover exact source IDs and return bounded document bytes. The coordinator checks public HTTPS origin, DNS, same-origin hrefs and cancellation; generic provider exceptions become sanitized status text. The local fake adapter is injected only by tests. The React pages provide file input, preview, field forms, history, search, portal connect/discover/import/cancel/retry and English/German labels.

## Remaining limits

Production wiring, vault callbacks and commercial portal adapters remain with the supervisor. Bot runs are process-local; a restarted run requires fresh discovery, and no scheduling adapter is registered. The document index and blobs require inclusion in the supervisor's coordinated backup/restore design. OCR language support is English only until a verified isolated German asset is supplied. The conservative parser requires human correction for layouts it cannot identify. PDF scanning rejects known active constructs, but this worker has not established complete PDF sanitization against every parser differential; a production release needs a dedicated adversarial corpus and sandbox review. Full-app browser and production authorization qualification remain pending integration.
